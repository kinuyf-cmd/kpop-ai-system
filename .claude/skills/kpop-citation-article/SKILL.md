# KPOP Citation Article

## 1. 目的

KPOP JOURNAL の記事供給の主軸は「引用記事」である。韓国系の主要メディアや
プレスリリースが報じた事実を、**日本語読者向けに翻訳・要約して紹介する**。
ゼロから事実を創作しないため、独自記事よりハルシネーションのリスクが構造的に
低い。その代わり「引用の作法」を厳密に守ることが品質と適法性の両方を支える。

このスキルは Layer 1(主要メディア引用)と Layer 2(リリース引用)の記事生成を
担う。Layer 3(旅行/ドラマ/グルメの独自記事)は別スキル `kpop-original-article`。

## 2. 引用記事の鉄則 — 主従関係の質的判断

著作権法32条の引用は「自社の表現が**主**、引用が**従**」であって初めて
成立する。本スキルでは主従関係を**質的判断**で担保する(オーナー判断
2026-05-20、§3 の Layer 別上限と組み合わせて運用):

- **質的判断の柱**: 自社のリード文 + 文脈付与(背景・整理・今後の見通し)+
  出典明記 + 公式リンク。これらを満たした上で、Layer 別の量的上限内に
  抑える。
- 引用元をなぞるだけの記事は (a) 著作権上の引用の要件を満たさず、
  (b) 検索エンジンに重複コンテンツとみなされ評価されず、(c) 読者に独自
  価値を与えない。だから引用記事といえども**記事の実体は自社の解説・
  整理**である。
- 全文転載は禁止(引用の要件を満たさず、適法性を失う)。
- 記事末尾に**引用元の明記とリンクが必須**(著作権法32条「出所明示」、
  §5)。

引用率の量的上限は **Layer 別**(§3-1)。出典フォーマット・ライセンス
(画像/動画/音楽)の詳細は `citation-rules` スキルに従う。本スキルは
その運用版である。

## 3. 記事の構成テンプレート(Layer 1 / Layer 2 共通)

引用記事は次の構造で生成する。`<h2>` は3個以上(監査要件)。

```
<h1> 日本語タイトル(原題の翻訳 + 読者に伝わる補足)
<p>  リード文(2-3文。何のニュースかを最初の一画面で伝える)
<h2> 見出し1: 出来事の要点
<p>  自社要約(原文の事実を日本語で整理)
<blockquote> 推奨: 原文の核心を直接引用(任意、§7 参照)
<h2> 見出し2: 背景・経緯
<p>  読者の前提知識を補う背景説明(過去の関連動向など)
<h2> 見出し3: 今後の見通し / 関連情報
<p>  わかっている範囲の今後。憶測は書かない(§6 はハルシネーション制御、翻訳ルールは §4)
<hr>
<p class="kpop-citation-source"> 引用元: <a href="原URL" rel="nofollow noopener">メディア名「原題」</a>(取得日 YYYY-MM-DD)
```

- 本文(HTMLタグ除去後)は **3000字以上**(pre_publish_gate / post_audit と一致)。
- 見出しは「H2が3個以上」。引用記事でも背景・見通しを足せば自然に満たせる。
- メタディスクリプションは **110-130字**。本文の単純コピーにしない。

### 3-1. Layer 別 引用率上限(2026-05-20 改訂、オーナー最終判断)

引用率の量的上限は Layer ごとに異なる:

| Layer | 内容 | 引用率上限 | カテゴリ判定 |
|---|---|---|---|
| **Layer 1** | 主要メディア引用(Soompi / Newsen / 韓国系英字メディア等) | **80%** | `news` / `comeback` / `chart` / `live` / `beauty` / `celeb` 等 |
| **Layer 2** | リリース引用(PRTIMES / プレスリリース) | **60%** | `event` / `popup` / `release` |
| **Layer 3** | 独自記事(旅行/ドラマ/グルメ、別 skill `kpop-original-article`) | **20%** | `travel` / `kdrama` / `fashion` / `oshikatsu` 等 |

上限は `post_audit.sh [14] Factcheck` でカテゴリから自動判定して適用する。
Layer 1 が80%まで許される根拠: 質的判断(リード+文脈+出典)を満たした上で、
事実報道(ランキング・公式発表など)を日本語読者向けに整理することが
記事の主目的であり、原文事実の比重が大きくなる構造的必然があるため。
ただし出典URL不在は引き続き HARD_FAIL(著作権法32条「出所明示」遵守)。

### 3-2. 速報(breaking)の字数例外(2026-05-22 オーナー判断)

カムバ発表・ツアー日程・スケジュールポスター公開などの**速報**は、出典が
2-4文の短報であることが多い。これに §8-4 の「本文3000字以上」を機械適用
すると、引用元に無い背景を水増しせざるを得ず §6(ハルシネーション禁止)と
衝突する。そこで速報には**字数要件を緩和**する:

- **速報の本文目安は 800-1200 字**(3000字必須を適用外)。判定キーは
  タイトル【速報】prefix または カテゴリ `news`/`comeback` かつ urgency=high。
- **書くのは出典にある事実のみ**(日付・会場・曲名・時刻など)。背景は
  アーティストの**確定済み公式情報のみ**(Idol Wiki由来=デビュー年・既発表等)。
  推測・憶測・引用元に無い数値は一切足さない(§6 厳守、ハルシネーション回避最優先)。
- H2 は 2 個以上で可(速報は「発表内容」「今後の予定/補足」の2本立てで自然)。
- 続報が出たら同記事に加筆 or 続報記事でフォローする前提。
- それ以外(短報でない通常の Layer1/L2)は従来どおり 3000字以上を維持。

## 4. 翻訳ルール

翻訳辞書 `~/.kpop_recovery/translation_dict.json` を**最優先で適用**してから
残りを翻訳する。辞書は3カテゴリ:

- `person_group`: 人名・グループ名。表記揺れを正式表記に固定
  (「방탄소년단」「防弾少年団」→ どちらも `BTS`)。
- `terms`: K-POP特殊用語(`컴백`→カムバック、`음방`→音楽番組 等)。
  直訳が不自然なものを自然な日本語に。
- `single_char`: 一文字ハングル等、翻訳せず原表記を保持すべきもの。

翻訳の品質基準:

- 直訳調を避ける。日本語として自然な記事文体にする(AI臭・翻訳臭は
  `audit-rules` / sanitize の検出対象)。
- 固有名詞は辞書 → 公式表記 → 原音カナの優先順位。
- 辞書に無い人名・用語に出会ったら、その記事では文脈から最善の表記を当て、
  **辞書への追加候補としてログに残す**(辞書はオーナーが育てる)。
- **翻訳者の明記は不要**(2026-05-20 オーナー判断、簡略化)。守るべきは
  「原文の趣旨を歪曲しない正確性」のみ。「翻訳: KPOP JOURNAL 編集部」
  等の署名や、翻訳責任者の付記は記事に書かない。

## 5. サムネイル取得・保存ポリシー(2026-05-20 改訂)

引用記事のサムネは**自社 WP uploads に複製保存**する。著作権法32条の引用
要件(主従関係・出典明記・必要最小限)を満たす限り合法であり、hotlink
(URL直参照)は元サイトの帯域に依存して表示が不安定になる・利用規約で
明示的に禁じている媒体があり得る、という運用上の欠点が大きいため。

> 改訂前(2026-05-20 まで): 「引用元URLを直接参照、自社サーバーには複製しない」
> 改訂理由: オーナー判断(2026-05-20)。著作権法32条の引用要件を満たす限り
> 複製保存も合法。hotlink は元サイト負荷 + 表示不安定 + 規約違反リスクで
> かえって不利。詳細は [[M3_stage3.8_skill_revision]] を参照。

### 5-1. 取得フォールバックの順序

1. **引用元サムネ**: 引用記事の OGP `og:image`、無ければ本文先頭の主要画像URL。
2. **アーティスト Wikipedia 画像**: 引用元に画像が無ければ、`translation_dict`
   のグループ名から Wikipedia API で代表画像URLを取得。
3. **なし**: 上記いずれも得られなければサムネ無しで進める(無理に埋めない)。
4. **関連画像生成(最終手段)**: それでも必要なら DALL-E で生成。ただし
   **人物像は生成しない**(実在人物の捏造画像を避ける)。会場・ロゴ・
   モチーフなど人物以外に限る。

### 5-2. 複製保存の必須要件(著作権法32条「引用」を満たす条件)

複製を合法にするための条件。1つでも欠けたら hotlink にフォールバックする。

- **記事末尾に引用元 URL 明記**(必須、`post_audit.sh [14]` で検証)
- **引用率 20% 以下**(著作権法32条、`post_audit.sh [14]` で監視)
- **サムネ `alt` または `<figcaption>` に「出典: <媒体名>」を必須明記**
  例: `<img class="kpop-cite-thumb" alt="出典: Soompi - <記事タイトル翻訳>" ...>`
- **主従関係**: 自社の要約・整理が80%以上、引用は20%以下
- **画像の改変なし**: 縦横比保持、リサイズ・再圧縮・トリミング・加工いずれも禁止
  (原本そのままのバイト列で保存する)

### 5-3. 保存先と命名

- 保存先: `wp-content/uploads/YYYY/MM/`(WordPress 標準の Media Library)
- WP attachment として正しく登録する(`wp_posts.post_type='attachment'` +
  `wp_postmeta._wp_attached_file` + `wp_postmeta._wp_attachment_metadata`)
- ファイル名は引用元のファイル名を維持(可能なら)、または
  `cite-<source_slug>-<記事 slug>.<ext>` の規則で衝突回避

### 5-4. hotlink フォールバック条件(複製禁止が明示されている場合)

次のいずれかに該当する場合は**複製せず**、`<img src="引用元URL">` で hotlink する:

- 引用元の利用規約・robots.txt・画像ライセンス表記が **画像の複製・再配布を明示的に禁じている**
- 引用元が画像 hotlink を明示的に許可している(オープンライセンス・配信用APIを提供している等)
- 月次 robots.txt 再確認で複製ポリシーが追加された

複製/hotlink の判断は媒体ごとに `~/.kpop_recovery/media_copy_policy.json` に
記録(段階3.6 の採用可否マトリクスと連動。Day 6 以降で運用)。

### 5-5. 表示規則(子テーマCSS `.kpop-cite-thumb` と連動)

- 縦横比を保持する(歪ませない)。
- 画質を落とさない(複製時に再圧縮しない、原本バイト列のまま保存)。
- 横幅はコンテナ内に収める(`max-width:100%; height:auto`)。見切れ厳禁。

サムネの比率・画質・関連性の検証は公開前後監査(`audit-rules` / `post_audit.sh [15]`)
が Pillow で行う。生成側は「正しい候補を選ぶ」ことと「複製の合法要件を満たすこと」
の両方に責任を持つ。

## 6. ハルシネーション制御 — 引用記事ならではの守り方

引用記事は「引用元に書いてあること」だけを書く。これが最大の防御である。

- **引用元に無い事実を足さない**。日付・数値・固有名詞・発言は引用元に
  あるものだけ。背景説明で過去の出来事に触れる場合も、確実な既知情報に限る。
- **憶測を断定で書かない**。「〜とみられる」「〜の可能性」を、引用元が
  そう書いていないのに付けない。逆に引用元が断定していないことを断定にしない。
- **Factcheck**: 生成した記事の各事実が引用元記事に対応するかを照合する。
  対応の取れない記述は削除するか、引用元を追加する。この照合結果は監査
  (post_audit の Factcheck 項目)に渡す。
- ゴシップ・センシージョン系の話題は一次ソースを優先し、確証のない
  噂レベルの情報は扱わない(`citation-rules` のNG引用、audit-rules の
  ゴシップソースガードと連動)。

## 7. blockquote / インライン style / table — 出力時の作法

### 7-1. blockquote の利用(2026-05-20 改訂)

引用部分の `<blockquote>` 利用は **推奨**だが、**厳密な区別は不要**
(オーナー判断、簡略化)。本文中に翻訳引用文を地の文として直接埋め込んでも
よい。守るべきは出典の明示(末尾の引用元URL + サムネ alt の「出典:媒体名」)
であり、視覚的に引用箇所を区切る方式は記事の自然さに応じて柔軟に選ぶ。

視覚的区別をつけたい場合は子テーマCSS で柔軟に対応する:

- `<blockquote>` を使う(従来通り、CSS で字下げ・縦線等)
- 地の文に `<span class="kpop-cite-text">…</span>` で軽い目印(任意、必須ではない)
- 何もマークしない(地の文として埋め込む)

どの方式でも、**引用元 URL の末尾掲載と、§3-1 の Layer 別引用率上限**を
守ること。これだけで著作権法32条の「出所明示」+ 主従関係(質的判断)の
要件を充足する。

### 7-2. インライン style

記事本文HTMLに **インラインの `style="color:…"` / `style="background:…"` を
書かない**。色はテーマ(子テーマCSS)のクラスに委ねる。これは過去に
生成記事のインライン色がアクセシビリティ基準(WCAG AA コントラスト)を
満たさず、サイト全体の品質ゲートで問題になったため。色を付けたい要素は
クラス名(例: 引用元リンクは `.kpop-citation-source`)を使う。

### 7-3. table 属性

表を出す場合は `<table>` に見出しセル `<th scope="col">` と `<caption>` を
付ける(スクリーンリーダー対応)。これらが無いと監査で警告になる。

> 補足: パイプライン側の sanitizer がインライン色や table 属性を最終的に
> 矯正する防御層を持つが、生成段階で正しく出力するのが本筋である。

## 8. HARD_FAIL 条件(2026-05-20 改訂、7条件)

次のいずれかに該当する記事は公開せず差し戻す。Layer 別引用率上限は §3-1。
**「翻訳者明記なし」は撤廃(オーナー判断 2026-05-20)**:

1. **引用元リンク・出典 URL が無い**(著作権法32条「出所明示」違反、必須)
2. **引用率が Layer 別上限を超える**(L1=80% / L2=60% / L3=20%、`post_audit.sh [14]` がカテゴリから自動判定)
3. **引用元に無い事実**(日付・数値・発言)を含む(Factcheck 不一致、ハルシネーション)
4. **本文 3000 字未満、または H2 が 3 個未満**
5. **メタディスクリプションが 110-130 字の範囲外**
6. **AI 定型文・AI 臭フレーズの混入**(「以下に記事を」「AIが生成」等)
7. **本文にインライン `color` / `background` が残存**(C-Y 防御層が機能していない徴候)

補助監査(重大度別、HARD_FAIL ではないが品質低下):
- 既存記事とタイトル/本文が高類似(連投・重複)= `post_audit.sh [16]` CRITICAL
- 引用元 URL の到達性失敗 = `post_audit.sh [14]` HIGH
- サムネ画質/比率 NG = `post_audit.sh [15]` HIGH
- 漢字率 > 30% / 平均文長 > 60字 = `post_audit.sh [17]` MEDIUM

## 10. 出力ルール

- 生成するのは記事HTML本体 + メタ情報(タイトル・ディスクリプション・
  スラッグ案・カテゴリ案)。スラッグは英語。
- 余計な前置き(「以下に記事を生成します」等)を出力しない。
- 翻訳辞書に追加すべき新語に気づいたら、記事とは別にログとして報告する。
