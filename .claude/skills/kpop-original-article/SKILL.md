# KPOP Original Article

## 1. 目的

KPOP JOURNAL の記事供給は「引用記事中心の3層パイプライン」である。本スキルは
その **Layer 3 = 独自記事(オリジナル SEO 記事)** の生成ルールを担う。

- Layer 1(主要メディア引用)/ Layer 2(リリース引用)は `kpop-citation-article`。
- Layer 3 = 旅行 / 韓国ドラマ / グルメ / コスメ / 推し活ガイド 等、**引用元の事実を
  なぞるのではなく、自社が一次的にテーマを企画して書き起こす記事**。

独自記事は引用記事と違い「引用元に書いてあること」という外部の足場が無い。
そのため (a) ハルシネーションのリスクが構造的に高く、(b) 独自価値が無いと
検索エンジンにも読者にも評価されない。本スキルは独自記事の品質を、構成テンプレ・
独自性要件・出典明記・**3ペルソナ・ゲート**で担保する。

## 2. 独自記事の鉄則 — 自社の一次表現が主、引用は最小限の従

独自記事は自社の企画・取材・整理が記事の実体であり、引用は補助でしかない。

- **引用率 20% 以下**(`citation-rules` §2 と整合。`post_audit.sh [14]` が
  Layer 3 = 上限 0.20 で自動判定)。独自記事で引用が 20% を超えるのは、それは
  もはや引用記事(Layer 1/2)であり、本スキルの対象ではない。
- 事実(数値・価格・住所・営業時間・放送日・配信先など)を書く場合は
  **必ず出典を明記**する(§5)。出典の無い具体的数値は書かない。
- 自社の解説・比較・整理・体験的視点が記事の主であること。一覧の羅列だけ・
  どこかの記事の言い換えだけ、にしない。

引用率の量的上限・出典フォーマット・ライセンス(画像/動画/音楽)の詳細は
`citation-rules` スキルに従う。本スキルはその独自記事向けの運用版である。

## 3. 記事の構成テンプレート(Layer 3 共通)

独自記事は次の構造で生成する。`<h2>` は3個以上(監査要件)。**3ペルソナ
それぞれの value が構造上どこかに入る**よう、見出しを設計する(§4 の対応表)。

```
<h1> 日本語タイトル(検索意図に答える + テーマの便益)
<p>  リード文(2-3文。誰の何の悩み/関心に答える記事かを最初の一画面で伝える)
<h2> 見出し1: そもそも〜とは / 基礎の整理 ← ペルソナ① 初心者向け説明
<p>  前提知識を持たない読者にも分かる言葉で背景・基礎を説明
<h2> 見出し2: 本題の深掘り / 比較 / 詳細 ← ペルソナ③ 検索流入が求める核心
<p>  検索意図(「方法」「比較」「おすすめ」「行き方」等)に具体的に答える
<h2> 見出し3: ファン目線の深掘り / 推し活的価値 ← ペルソナ② コアファン向け
<p>  グループ名・楽曲・聖地・推し活の文脈など、ファンが刺さる固有情報
<h2> 見出し4(任意): まとめ / 次の一歩
<hr>
<p class="kpop-citation-source"> 参考: <a href="原URL" rel="nofollow noopener">媒体名「記事名」</a>(取得日 YYYY-MM-DD) ← 事実引用がある場合のみ
```

- 本文(HTMLタグ除去後)は **3000字以上**(pre_publish_gate / post_audit と一致)。
- 見出しは「H2が3個以上」。3ペルソナ構成にすれば自然に満たせる。
- メタディスクリプションは **110-130字**。本文の単純コピーにしない。

## 4. 【中核】3ペルソナ視点の必須化 — 3ペルソナ・ゲート

独自記事は **3つのペルソナ全員に価値を届ける**ことを必須要件とする
(100点計画 C-4「3ペルソナ視点 必須化」)。1ペルソナだけに刺さる記事は
読者層を取りこぼし、回遊・指名検索・収益のいずれも伸びない。

### 4-1. 3ペルソナの定義

プロジェクトのターゲット層定義(`docs/operations_runbook_v1.0.md`
「ターゲット層適合性の担保箇所」)を3類型に集約する。

| # | ペルソナ | 誰か | この読者が記事に求める value |
|---|---|---|---|
| **①** | **K-POP初心者 / ライト層** | これからK-POPに触れる人、にわか、家族・友人に勧められた層 | 専門用語に頼らない**基礎の説明**。「そもそも〜とは」「初めての人向け」「わかりやすく」 |
| **②** | **コアファン / オタク(推し活層)** | 特定グループの熱心なファン、推し活実践者 | グループ名・メンバー・楽曲・聖地・グッズ等の**固有の深掘り**。推し活的な実用情報 |
| **③** | **検索流入の一般読者** | 「韓国 カフェ おすすめ」等で検索して来た、特定の答えが欲しい層 | 検索意図に**具体的に答える結論**。比較・手順・価格・行き方・配信先など |

### 4-2. 3ペルソナ・ゲート(公開前の必須チェック)

各記事が3ペルソナ全員をカバーしているかを公開前に検査する。検査は
`post_audit.sh [14b] 3ペルソナ・ゲート` が自動で行う(§実装は後述)。
判定は見出し・キーワードの**有無**で行い、明確な欠落のみを検出する
(誤検知を避ける。通常の記事フレーズを誤ブロックしない — [[feedback_guard_false_positives]])。

各ペルソナの「カバーされている」signal(いずれか1つでも該当すれば充足):

- **ペルソナ① 初心者向け説明**:
  見出し or 本文に「とは」「基礎」「初心者」「入門」「はじめて / 初めて」
  「わかりやすく」「基本」「そもそも」「知らない人」のいずれか。
- **ペルソナ② ファン向け深掘り**:
  本文に具体的なグループ名/アーティスト名(`translation_dict.json` の
  `person_group` に載る固有名)、または「推し」「ファン」「メンバー」
  「ペンライト」「聖地」「グッズ」「カムバック」等のファン文脈語のいずれか。
- **ペルソナ③ 検索意図への結論**:
  見出し or 本文に「おすすめ」「比較」「方法」「やり方」「行き方」「選び方」
  「ランキング」「まとめ」「徹底解説」「料金 / 価格」「アクセス」のいずれか、
  または「まとめ」系の結論 H2 が存在。

3つすべての signal が揃えば **3ペルソナ・ゲート PASS**。1つでも欠ければ検出。

### 4-3. 設計時の指針(生成側の責任)

生成段階で 3-2 の構成テンプレに沿えば、ゲートは自然に通る。
形式的にキーワードを撒くのではなく、各見出しが**実際にそのペルソナの
疑問に答えている**かを確認する。例(テーマ=「韓国 ソウル カフェ」):

- ① 「韓国カフェ文化とは?日本との違いを基礎から」
- ③ 「エリア別おすすめカフェ7選と行き方・予算の比較」
- ② 「推しの聖地巡礼に使えるカフェ — ◯◯(グループ名)ゆかりの店」

## 5. 出典明記 — 独自記事でも事実には足場を

独自記事は引用に頼らないが、**検証可能な事実(価格・住所・営業時間・放送日・
配信プラットフォーム・受賞歴・数値)を書くときは出典を明記する**。

- 出典フォーマットは `citation-rules` §3 に従う(媒体名 + タイトル + URL + 取得日)。
- 末尾に `<p class="kpop-citation-source">参考: <a href=... rel="nofollow noopener">…</a></p>`。
- 公式情報源を優先(`citation-rules` §5 の Tier。公式サイト/Billboard/Korea JoongAng Daily 等)。
- 出典の無い具体的数値・統計は書かない(`citation-rules` §6 NG引用)。
  「だいたい」「諸説あるが」で逃げて断定しないこと。

## 6. SEO要件

- タイトルに主要検索キーワード + 便益 + 必要に応じて年号。
- メタディスクリプション 110-130 字、検索意図に答える要約。本文コピー禁止。
- 見出し H2 に検索キーワードを自然に含める(キーワード詰め込みは不可)。
- スラッグは英語、内容を表すもの。先頭数字・汎用スラッグ禁止
  (`post_audit.sh [0]` スラッグ検査と整合)。
- 内部リンク(関連する自社記事 / Idol Wiki)を1本以上(SEO 回遊)。

## 7. ハルシネーション制御 — 独自記事ならではの守り方

独自記事は外部の足場が無いぶん、引用記事より能動的に検証する。

- **検証できない固有情報を断定で書かない**。実在の店名・住所・営業時間・
  価格・放送日・配信先・メンバーの発言などは、出典で裏が取れたものだけ。
- **実在人物の私的事実・未確認のゴシップは書かない**(`citation-rules` のNG引用、
  `audit-rules` のゴシップソースガードと連動。gossip は一次ソース必須)。
- **架空のグループ名・楽曲名・イベントを作らない**。固有名は
  `translation_dict.json` の `person_group` 等の既知情報に当てる。
- 旅行・グルメ記事の「現在も営業しているか」等、時間で変わる事実は
  「YYYY年MM月時点」と取得時点を添える。

## 8. インライン style / table — 出力時の作法

`kpop-citation-article` §7 と同一ルール(独自記事も同じ品質ゲートを通る)。

- 本文HTMLに **インライン `style="color:…"` / `style="background:…"` を書かない**
  (C-Y。配色は子テーマCSSのクラスに委ねる。WCAG AA 維持)。
- 表は `<table>` に `<th scope="col">` と `<caption>` を付ける(C-Z、SR対応)。
- 色を付けたい要素はクラス名(例: 引用元リンクは `.kpop-citation-source`)。

> 補足: パイプライン側 sanitizer が最終的に矯正する防御層を持つが、
> 生成段階で正しく出力するのが本筋。

## 9. HARD_FAIL 条件(独自記事 = Layer 3)

次のいずれかに該当する記事は公開せず差し戻す。引用記事の HARD_FAIL
(`kpop-citation-article` §8)と共通の項目に加え、独自記事固有の
**3ペルソナ・ゲート**を必須とする。

1. **3ペルソナのうち1つでも視点が欠落している**(3ペルソナ・ゲート不成立、
   `post_audit.sh [14b]` が CRITICAL = HARD_FAIL。C-4 必須化の実体)
2. **引用率が Layer 3 上限 20% を超える**(`post_audit.sh [14]`、§2)
3. **出典の無い具体的数値・固有事実**を断定で含む(ハルシネーション、§7)
4. **本文 3000 字未満、または H2 が 3 個未満**
5. **メタディスクリプションが 110-130 字の範囲外**
6. **AI 定型文・AI 臭フレーズの混入**(「以下に記事を」「AIが生成」等、
   `post_audit.sh [1b]` NGワード検出)
7. **本文にインライン `color` / `background` が残存**(C-Y 防御層の徴候)

補助監査(重大度別、HARD_FAIL ではないが品質低下):
- 既存記事とタイトル/本文が高類似(連投・重複)= `post_audit.sh [16]` CRITICAL
- 内部リンク 0 = `post_audit.sh [1b]` LOW
- サムネ画質/比率 NG = `post_audit.sh [15]` HIGH
- 漢字率 > 30% / 平均文長 > 60字 = `post_audit.sh [17]` MEDIUM

> **適用範囲**: 3ペルソナ・ゲートは **Layer 3(独自記事)専用**。
> Layer 1 / Layer 2 引用記事は対象外(引用記事は引用元の事実整理が主目的で、
> 3ペルソナ構成を強制すると引用の主従関係を崩すため)。`post_audit.sh [14b]`
> はカテゴリ slug → Layer 判定([14] の `CITE_LAYER`)を再利用し、
> **Layer 3 のときだけゲートを発火**する。

| C項目 | このスキルの寄与 |

## 11. 出力ルール

- 生成するのは記事HTML本体 + メタ情報(タイトル・ディスクリプション・
  スラッグ案・カテゴリ案)。スラッグは英語。
- 余計な前置き(「以下に記事を生成します」等)を出力しない。
- 3ペルソナのうち弱い視点に気づいたら、その見出しを補ってから出力する
  (公開前にゲートで弾かれる前に生成側で直すのが本筋)。
