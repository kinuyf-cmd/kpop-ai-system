### 0. 最重要ミッション
KPOP JOURNALを、**データドリブンで自律改善するAIメディア企業OS**として運用する。

目的:
1. 毎日安定して高品質記事が自動投稿される
2. 誤投稿・審査レポート投稿・質問文投稿をゼロにする
3. 検索流入とX流入を両立する
4. 記事単位ではなく、カテゴリ単位・事業単位で収益を最大化する
5. トークンコストを抑えながら利益率の高い運用にする
6. 日次・週次・月次で経営判断ができる状態にする
7. 将来的に月商100万円超、さらにバイアウト/法人化に耐える運営基盤にする
8. 全ての実行データを計測し、フィードバックループで自律改善する
9. 投稿→計測→改善のサイクルを24時間以内に回す
10. **【v1.3追加】ミュウツーの戦略判断を起点とし、全パイプラインが「何を書くべきか」から始まる**

### 1. 経営理念

理念は「かけふ＋まわす」。

- か：稼ぐ — 収益を最大化する
- け：削る — 無駄なコスト・重複を排除する
- ふ：防ぐ — 誤投稿・炎上・品質低下を防ぐ
- **ま：回す — 計測→分析→改善のサイクルを止めない**

行動原則:
- 自立して動け
- 止めるな
- 改善しろ
- ただし壊れたものは出すな
- 迷ったら止めるより警告付きで前進
- **【v1.3変更】速報は「本当に速報であるもの」だけ速報として出す**
- 資産記事は品質優先
- 収益記事はCV優先
- 投稿より「正しい投稿」を優先
- 計測できないものは改善できない。全アクションにメトリクスを。
- 昨日のデータが今日の判断を変える。フィードバックなき実行は惰性。
- **【v1.3追加】同じネタを繰り返すな。直近3日間の投稿と被らないテーマを選べ。**
- **【v1.3追加】エージェントが失敗しても全体は止めるな。フォールバックで前進せよ。**

### 9. SEO設計

内部リンク:
- 最低2本
- 同カテゴリ優先
- 直近記事1本 + evergreen記事1本
- `add_internal_links.sh` で自動挿入（投稿直後に実行）

メタディスクリプション:
- 110〜130字
- `post_to_wp.py` で文境界区切りで自動生成

Google / Bing インデックス:
- 投稿直後に送信（`request_index.sh` / `request_bing_index.sh`）
- 失敗時3回再試行（指数バックオフ: 5秒→10秒→15秒）
- **【v1.3追加】全CTAスクリプトに`.env`自動読み込みを追加（認証失敗防止）**

SEOフィードバックループ:
- 毎朝6:00に `fetch_yesterday_metrics.py` でGSC/GA4データ取得
- **【v1.3追加】トラフィックソース別セッション数を計測（X流入 = t.co + x.com）**
- CTR下位記事を自動抽出
- **【v1.3追加】毎週木曜 6:00に `update_low_ctr_titles.sh` で低CTRタイトルを自動リライト**
- 対象記事リストを `logs/rewrite_candidates.jsonl` に蓄積

収益導線:
- `inject_revenue_links.sh` で「あわせて読みたい」ブロックを自動挿入
- `inject_abema_cta.sh` でABEMA関連記事にCTA挿入
- カテゴリ別マッピング: ライブ→イベントガイド、美容→コスメ記事、旅行→ホテルガイド

### 10. X自動投稿ルール

- `ENABLE_X_POST=1` で本番投稿、未設定でdry-run
- `score_x_post.py` でスコア5以上を要求（不合格時はarticunoで再生成、再不合格でスキップ）
- 全パイプラインから`post_to_x.sh`経由で投稿

メイン投稿:
- 強い導入（結論ファースト）
- 記事URL
- ハッシュタグ2〜3（#KPOP必須 + アーティスト名）
- 記事内容と一致
- **【v1.3追加】ターゲット: 10-30代の女性K-POPファン**

**【v1.3改訂】X投稿ログ:**
- 全投稿結果を `/logs/x_post.log` に記録（成功/失敗/DRY-RUN/スキップ）
- `summary.txt` に `X投稿: 成功(URL)` or `失敗` を追記
- 全パイプライン（ニュース・戦略・チャート）で統一ログ形式

X投稿効果測定:
- `fetch_yesterday_metrics.py` でGA4のトラフィックソース別セッション数を取得
- `x_sessions` フィールドで t.co / x.com / twitter.com からの流入を集計
- 高パフォーマンス投稿パターンを `logs/x_performance.jsonl` に蓄積
- 月次でペルシアンのプロンプトにフィードバック

### 11. スコアリング

各項目10点満点、合計50点。（scoring_hook.md準拠）

判定:
- 45〜50：投稿
- 38〜44：軽微修正
- 30〜37：リライト必須
- 29以下：却下

スコアの記録と活用:
- アルセウスの採点結果からスコアを抽出
- `kpi_posts.jsonl` の `score` フィールドに記録
- 週次でスコア分布を分析し、低スコア傾向のエージェントを特定
- **【v1.3追加】週次改善サイクル（ポリゴン→ルギア）でエージェント別スコアを評価し、改善指示を生成**

**【v1.3追加】サブスコアリング:**
- タイトルCTR: `score_title_ctr.py` スコア7以上（警告のみ、投稿は続行）
- サムネ文言: `score_thumbnail_text.py` スコア5以上（NG時1回リトライ→タイトルから自動抽出）
- X投稿文: `score_x_post.py` スコア5以上（NG時articunoで再生成→再NGでスキップ）

### 12. トークン削減・コスト最適化

原則:
- 毎日同じルールはhook化（9フック実装済み）
- 記事タイプごとに必要エージェントだけ起動
- 中間出力は短く
- **【v1.3追加】ジラーチには外部ツールを渡さない（トークン節約＋失敗防止）**

トークントラッキング:
- `ENABLE_TOKEN_TRACKING=1` で有効化
- `lib/claude_wrapper.sh` が全 `claude` 呼び出しをラップし、usage情報を `$TOKEN_LOG` に蓄積
- パイプライン終了時に `token_total` で合計を算出
- `lib/token_report.py` で日次/週次/月次のトークンコスト集計
- CEO Morning Briefに前日トークンコストを表示
- 目標: 1記事あたりの平均トークンコストを月次で5%ずつ削減

**【v1.3追加】コスト最適化の実績:**
- ニュースパイプライン: 7エージェント（ミュウツー+6体）
- 戦略パイプライン: 15エージェント（高品質だがコスト高）
- テーマ記事: 6エージェント（テーマ指定でリサーチ省略）
- パイプライン別コスト目標: ニュース<100円、テーマ<80円、戦略<200円

### 18. 監査・障害対応

BLOCK条件（post_guard.py）:
- タイトルなし / 本文なし / 質問文 / 審査文 / HTML破損
- 投稿対象ファイル不一致 / 文字数不足 / h2が4個未満
- **【v1.3追加】Claude APIレスポンスJSON混入（sanitize_outputで自動除去）**
- **【v1.3追加】英語エラーメッセージ混入（"Web tools are currently blocked"等）**

緊急停止トリガー（safety_config.json）:
- 連続失敗3回 / 日次エラー5件 / WP API 5xx 3回 / トークン予算超過

手動承認トリガー:
- 記事スコア38点未満 → 承認キューに入れる
- ゴシップ・炎上キーワード含む → アブソル審査
- 新カテゴリ初投稿 → CEO承認
- `lib/human_gate.py` の `request_approval()` をパイプラインから呼び出す
- Discord #urgent-errors に承認依頼を通知

**【v1.3追加】フォールバック機構:**
- ジラーチ出力が元記事の10%未満 → リライト版をそのまま使用（パイプライン停止しない）
- サムネ文言がスコアNG → タイトルから自動抽出（「緊急発表」等のデフォルト文言は使わない）
- CTA挿入失敗 → エラーログに記録して続行（2>/dev/null廃止、2>&1でログ可視化）

**【v1.3追加】パイプラインエラー時の異常検知:**
- `archive_and_exit` 時に `kpi_logger.log_error()` でエラー記録
- `human_gate.py check` で連続失敗チェック・自動停止判定
- エラー通知は Discord #urgent-errors に送信

**【v1.3追加】sanitize_output強化:**
- Claude APIレスポンスJSON（`{"type":"result"...}`）の自動除去
- HTML-encoded版JSONの除去
- リテラル `\n` の除去
- 英語エラーメッセージ（"Web tools are currently blocked" / "WebSearch requires a permission"）の除去
- 「学習データの範囲外」「知識カットオフ」等の辞退文の除去
