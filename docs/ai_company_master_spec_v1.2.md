### 0. 最重要ミッション
KPOP JOURNALを、**データドリブンで自律改善するAIメディア企業OS**として運用する。

目的:
1. 毎日安定して高品質記事が自動投稿される
2. 誤投稿・審査レポート投稿・質問文投稿をゼロにする
3. 検索流入とX流入を両立する
4. 記事単位ではなく、カテゴリ単位・事業単位で収益を最大化する
5. トークンコストを抑えながら利益率の高い運用にする
6. 日次・週次・月次で経営判断ができる状態にする
7. 将来的に月商100万円超、さらにバイアウト/法人化に耐える運営基盤にする
8. **【v1.2追加】全ての実行データを計測し、フィードバックループで自律改善する**
9. **【v1.2追加】投稿→計測→改善のサイクルを24時間以内に回す**

### 1. 経営理念
理念は「かけふ」。

- か：稼ぐ
- け：削る
- ふ：防ぐ

行動原則:
- 自立して動け
- 止めるな
- 改善しろ
- ただし壊れたものは出すな
- 迷ったら止めるより警告付きで前進
- 速報は速度優先
- 資産記事は品質優先
- 収益記事はCV優先
- 投稿より「正しい投稿」を優先
- **【v1.2追加】計測できないものは改善できない。全アクションにメトリクスを。**
- **【v1.2追加】昨日のデータが今日の判断を変える。フィードバックなき実行は惰性。**

### 7. 投稿ルール

#### 投稿対象ファイル
- final_post.md のみ

#### 記事構造
- 1行目：タイトル
- 2行目以降：HTML本文

- 導入 / 結論 / 詳細 / 背景 / 今後 / まとめ / CTA / 内部リンク を含む

#### 文字数
- 速報：1,500字以上
- 通常：2,500字以上
- 解説：4,000字以上
- 比較：5,000字以上

#### タイトルルール
- 28〜42文字推奨
- 数字必須
- 固有名詞2つ以上
- 主要KWを左寄せ
- `score_title_ctr.py` でスコア7以上を要求

#### スラッグルール
- 英数字とハイフンのみ
- 4〜8語
- 日本語禁止

### 9. SEO設計

内部リンク:
- 最低2本
- 同カテゴリ優先
- 直近記事1本
- evergreen記事1本

Google / Bing:
- 投稿直後に送信
- **失敗時3回再試行**（指数バックオフ: 5秒→10秒→15秒）
- `request_index.sh` / `request_bing_index.sh` にリトライ実装済み

**【v1.2追加】SEOフィードバックループ:**
- 毎朝6:00に `fetch_yesterday_metrics.py` でGSC/GA4データ取得
- CTR下位10記事を自動抽出
- 週次で `score_title_ctr.py` に通し、スコア5以下のタイトルをリライト候補としてDiscord通知
- 対象記事リストを `logs/rewrite_candidates.jsonl` に蓄積
- **リライトパイプライン**（新設）: 低CTR記事のタイトル・メタ・冒頭を自動改善してWP更新

### 10. X自動投稿ルール

- `ENABLE_X_POST=1` で本番投稿、未設定でdry-run
- `score_x_post.py` でスコア5以上を要求（不合格時はarticunoで再生成、再不合格でスキップ）
- 全パイプライン（速報・戦略・チャート・合議）からpost_to_x.sh経由で投稿

メイン投稿:
- 強い導入（結論ファースト）
- 記事URL
- ハッシュタグ2〜3
- 記事内容と一致

**【v1.2追加】X投稿効果測定:**
- 投稿後24時間のX流入をGA4で計測
- 高パフォーマンスツイートのパターンを `logs/x_performance.jsonl` に蓄積
- 月次でペルシアンのプロンプトにフィードバック

### 18. 監査・障害対応

BLOCK条件（post_guard.py）:
- タイトルなし / 本文なし / 質問文 / 審査文 / HTML破損
- 投稿対象ファイル不一致 / 文字数不足 / h2が4個未満

緊急停止トリガー（safety_config.json）:
- 連続失敗3回 / 日次エラー5件 / WP API 5xx 3回 / トークン予算超過

**【v1.2追加】手動承認トリガーの有効化:**
- 記事スコア38点未満 → 承認キューに入れる
- ゴシップ・炎上キーワード含む → アブソル審査
- 新カテゴリ初投稿 → CEO承認
- `lib/human_gate.py` の `request_approval()` をパイプラインから呼び出す

### 24.【v1.2新設】エージェント性能管理

#### エージェント別計測項目
- 平均トークン使用量（input/output）
- 平均処理時間
- 出力品質スコア（アルセウス採点）
- エラー率（出力空/フォーマット違反）
- コスト効率（スコア/トークン比）

#### 計測方法
- `claude_wrapper.sh` が `--agent` 引数からエージェント名を抽出
- `$TOKEN_LOG` にステップ名として記録
- 週次で `token_report.py` がエージェント別集計を出力

#### アクション基準
- エラー率 > 10%: プロンプト見直し
- トークン/記事 が平均の2倍超: 出力長制限追加
- スコア平均 < 6/10: hookの強化 or エージェント再設計
